# 持仓区只认本地账本，不扫全钱包、不借第三方盈亏口径

主面板「持仓」区列出 burner 钱包在本地账本里 confirmed 买过的币的链上余额（余额读数还多读一枚当前焦点币，供弹卡卡头用），外部转入的币不会出现在列表里。累计买入 / 卖出、盈亏（`usd + soldUsd − boughtUsd`）、K 线买卖均价线全部由本地 confirmed 记录推出，不掺任何第三方账户口径——这样每个数字都能回溯到我们自己签过的一笔交易，索引滞后、周期错位这类「对方账本和链上对不上」的状态根本不存在。

## Considered Options

- **全钱包扫描（链上索引器 / 第三方 balances 接口枚举全部持仓）**：能列出转入的币，但转入没有成本基准，盈亏 / 时长要么编要么留空；且列表会被空投碎屑塞满。持仓区的目的是「看我买的东西怎么样了」，不是资产总览。
- **复用 fomo.family「Your positions」的 `activeTrade` / `userToken` 盈亏公式**：调研过官网前端的 P/L 计算并能复刻，但它依赖对方索引器的交易周期；加仓 / 部分卖出 / 清仓重买后对方 raw 与链上 raw 不一致时，时长与盈亏全部要置空防陈旧，而且把转入按到账价计入成本，与我们「只算自己买的」口径冲突。最终放弃整条依赖。

## Consequences

- 价值 < $2 的碎屑只在 Swift 显示层过滤（`usd` 未知的照显；正在一键交易 / 刚落定的行例外照显），`trade_holdings` 快照与账本保持完整，弹卡、卖出刷新、均价线不受影响。
- 打开不在监听列表里的持仓时，引擎按 `chain:address` 建临时 TokenState（最多 8 份，最旧淘汰），走与追踪代币相同的行情 / K 线 / 社交管线，只对当前焦点以 `token_detail`（`holdingOnly=true`）推回；绝不进 `state`、不落库、不伪造喊单。
